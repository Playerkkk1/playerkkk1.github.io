# 友链与文章浏览量

配置日期：2026-11-01。实施前先核对主题原文档与本地代码：

- [原主题友链文档](https://docs-firefly.cuteleaf.cn/zh/guide/friends.html)：`friendsConfig.ts` 管理列表、权重及启用状态，`friends.mdx` 管理本站信息和申请说明。
- [原主题评论系统文档](https://docs-firefly.cuteleaf.cn/zh/guide/comment.html)：Twikoo、Waline、Artalk 的 `visitorCount` 依赖各自实际后端地址。

检查时，本博客的友链页面和「社交 → 友链」导航已经开启，但友链数组为空；评论系统为 `none`，后端地址是主题示例，不能通过打开开关得到真实浏览量。根据“没有后端，使用公共统计”的选择，文章计数独立接入不蒜子公共服务，评论继续保持原设置。

## 在 CMS 管理友链

1. 打开 Pages CMS，选择博客仓库的 `master` 分支。
2. 左侧打开「友链管理」，在「友链列表」点击 **Add an item**。
3. 填写站点名称、完整 HTTPS 地址、一句话介绍；头像可上传或选择已有图片，留空使用本站默认图标。
4. 标签每项一个；权重数字越大越靠前。「启用」关闭时暂时隐藏该友链。
5. 点击 **Save**，部署成功后访问 `/friends/`。有条目后，原有搜索和标签筛选自动出现。

「显示友链列表」可暂时隐藏整个列表而保留数据，页面和本站信息仍可访问。这个布尔字段也确保清空全部条目后，CMS 仍保存有效 JSON 文件。

真实友链尚未提供，因此初始列表保持为空，没有预置互换关系或虚构站点。数据文件是 `src/data/friends.json`，`links` 为空或被 CMS 清空时显示空状态；不回填主题示例。整个管理文件禁止通过 CMS 删除。

页面下方的站点介绍与申请说明保留原主题布局，头像读取当前个人资料。访客可通过页面的 GitHub 联系入口提供站点信息；没有启用评论系统，也没有新增自动接收或自动发布友链的接口。

## 文章浏览量

- 文章详情页标题下方显示「浏览量」，从公共服务取得真实 PV；首页文章卡片不逐项查询。
- 使用 [不蒜子公共服务](https://www.busuanzi.cc/doc.php) 当前脚本使用的统计接口 `https://cdn.busuanzi.cc/api.php`，读取 `busuanzi_page_pv`。这不是主题原生评论后端的计数功能。
- 计数标识为正式站点域名下的文章路径；参数和页内锚点不会产生新的计数标识。页面重载或离开后再次进入属于新一次访问，浏览量不等于独立访客数，也不等于实际读完次数。
- 本地预览、其他域名和分支部署不调用计数接口，显示 `—`，避免污染正式数据。
- 无刷新切换文章会更新计数；同一次页面访问中重复触发初始化不会重复请求，前一篇迟到的响应不会覆盖后一篇。
- 请求失败、响应异常或超过 8 秒时显示「统计不可用」，文章仍可正常阅读；不把失败伪装成 `0`。
- 从接入开始累计，不恢复接入前的历史访问量。数据由公共服务保存，可能受其可用性、规则变更或数据重置影响，不能用作精确审计或账务依据。

配置在 `src/config/pageViewConfig.ts`：`enable: false` 可关闭公共计数。若以后部署自己的评论后端，可关闭这里并按原主题文档设置对应 `visitorCount`；同时启用时优先显示独立公共计数，避免出现两组浏览量。

浏览器会向该服务发送文章规范地址和来源站点的域名；服务也会接收到网络请求的 IP 等信息。本站请求不携带 Cookie，也不发送来源页面的查询参数；没有加载它的远程可执行脚本。
