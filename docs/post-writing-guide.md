# 随手写文章与系列续写模板

适用当前 Firefly 博客，核对日期：2026-11-01。依据现有 Java、MySQL、后端与六级文章，以及实际内容 Schema、系列分组代码和 Pages CMS 配置整理。

**一次写清一个小主题，保存为一个 `.md` 文件；以后写新主题就新建文件，保持 `series` 相同、增加 `seriesOrder`。** 不需要预先写好整套教程。

可直接复制：[随手记录模板](./template-examples/quick-series-post.md) · [较完整的学习笔记模板](./template-examples/study-series-post.md)。复制到 `src/content/posts/` 下再修改；模板留在 `docs/` 时不会被文章集合发布。

## 1. 分类、系列、标签各填什么

| 字段 | 回答的问题 | 六级文章示例 | 填写习惯 |
| --- | --- | --- | --- |
| `title` | 这篇文章具体讲什么？ | `六级学习笔记 01：仔细阅读中的同义替换与干扰项` | 标题写清主题；序号可选，写了就与系列顺序保持一致 |
| `category` | 属于哪个大类？ | `英语六级` | 一个字符串，尽量沿用已有分类 |
| `series` | 属于哪一组持续更新的文章？ | `六级学习笔记` | 同系列逐字一致；不必每篇重复创建系列 |
| `seriesOrder` | 在这个系列中排第几？ | `1` | 数字不加引号，后续用 `2`、`3`；尽量不重复 |
| `tags` | 涉及哪些知识点？ | `[英语六级, 仔细阅读, 同义替换]` | 字符串数组，建议选 2～4 个有用关键词；这是写作建议，没有要求必须填满 |
| `description` | 读者能从这一篇得到什么？ | `整理同义替换和常见干扰项，记录自己的判断方法。` | 一句话即可，不要复制全文 |
| `published` | 这篇何时发布？ | `2026-11-01` | 手写文件时日期不加引号；按实际日期填写 |
| `draft` | 是否暂不展示？ | `true` | 写作时为 `true`，发布时改为 `false` |

例如现有 Java 文章用 `category: Java`、`series: "Java 学习笔记"`；后端文章用 `category: 后端开发`、`series: "后端学习笔记"`。标签可以因每篇内容不同而变化。

目录、文件名、标题中的“01”都不会自动建立系列，真正起作用的是 `series`。标签相同也不代表属于同一个系列。

## 2. 一级、二级标题放在哪里

| 层级 | 应该放的内容 | 是否新建文章 |
| --- | --- | --- |
| Frontmatter 的 `title` | 整篇文章的标题，主题会显示它 | 新文章有自己的 `title` |
| 正文 `# 一级标题` | 日常新文章通常省略，避免再次重复文章标题 | 标题层级本身不会生成新文章 |
| 正文 `## 二级标题` | 本篇的大段落，例如“今天的问题”“例子”“易错点” | 留在同一个 `.md` 文件里 |
| 正文 `### 三级标题` | 某个二级段落下的小主题，例如“扩大范围”“改变语气” | 留在所属二级标题下面 |

例如，一篇“同义替换与干扰项”的正文可以这样写：

```markdown
先用一两句话交代今天学了什么。

## 同义替换

### 怎么识别

### 我的例子

## 常见干扰项

### 扩大范围

### 改变语气

## 这次记住的判断方法
```

**是否拆篇，取决于是不是新的独立问题，而不是用了几个 `#`。** 上面这些内容共同解释一件事，可以写在一篇中。下次记录“长难句中的主干识别”，就是新主题，适合另建一篇，再放进同一系列。

现有集合笔记较长，现有 JSON 请求体笔记很短，两种长度都能正常作为一篇文章。无需为凑模板而硬写很多节；旧文章中的一级标题也不必为了这份约定批量调整。

## 3. 最适合随手写的正文

每次只回答三个问题：**今天弄懂了什么？用什么例子说明？下次怎么用？**

```markdown
今天在……遇到了……，这里记下这次弄懂的一点。

## 今天弄懂的一点

先用自己的话说结论，再补一句原因。

## 一个例子

写题目片段、代码、操作步骤或前后对比，并说明自己怎么看出来的。

## 下次怎么用

写一个可执行的判断步骤，或者记下还没弄懂的问题。
```

有报错就加“踩坑记录”，有对比就加表格，有结果就加代码输出或截图。没有这些内容就省略。技术文章的代码块标明 `java`、`sql` 等语言；正文图片使用实际上传后的 `/uploads/posts/...` 路径，或保留文章旁的相对图片路径。

引用课程、真题或文档时，记下实际年份、题号或来源链接；自己的例句标注为自拟例子，避免以后混淆。

## 4. 今天一篇，下次接着写

以下是组织示例，不表示这些新文件已经建立：

```text
src/content/posts/cet6-notes/
├── 01-reading-paraphrase.md
├── 02-sentence-structure.md
└── 03-listening-review.md
```

| 文章 | `category` | `series` | `seriesOrder` | `tags` 示例 |
| --- | --- | --- | --- | --- |
| 同义替换与干扰项 | 英语六级 | 六级学习笔记 | `1` | 英语六级、仔细阅读、同义替换 |
| 长难句主干识别 | 英语六级 | 六级学习笔记 | `2` | 英语六级、长难句、语法 |
| 一次听力错题复盘 | 英语六级 | 六级学习笔记 | `3` | 英语六级、听力、错题复盘 |

第一篇只写第一篇的内容，下一篇是新的文件；不用把后续全文追加在第一篇下面，也不用提前放空章节。发布新文章后，博客会按相同的 `series` 自动分组并更新系列导航。

系列内按 `seriesOrder` 从小到大排列；未填写顺序的文章排在已填写的后面，相同顺序再按发布日期降序、标题排列。首页仍主要按置顶状态和发布日期排序，系列序号不会把首页改成教程顺序。正式构建中的草稿不进入公开系列列表。

你当前已有的 `src/content/posts/英语/2026-11-01-.md` 已设置分类与标签，但还没有 `series`、`seriesOrder`。如果想让它成为第一篇，可在 CMS 中填写「系列名称」为 `六级学习笔记`、「系列顺序」为 `1`，保留原来的标签；需要补充的 Frontmatter 是：

```yaml
series: "六级学习笔记"
seriesOrder: 1
```

下一篇使用相同的 `series`，把 `seriesOrder` 改成 `2` 即可。原来的文件名可以保留，避免改动已发布文章的网址。现有 Java 系列已有第 21 篇；如需继续接在末尾，应从当前实际最大序号之后开始。

## 5. 完整 Markdown 与 CMS 正文怎么用

**在 VS Code 或 GitHub 编辑完整 `.md` 文件：** 复制模板的全部内容。第一行就是 `---`，它与第二个 `---` 之间是 Frontmatter；第二个 `---` 之后才是正文。保存为 UTF-8。

**在 Pages CMS 写文章：** 标题、日期、分类、标签、摘要等填上方表单；正文框只粘贴模板第二个 `---` 之后的内容。不要把整个 Frontmatter 粘进正文 Source，否则它只会成为正文文字，不会设置系列。

CMS 文章表单已提供「系列名称」与「系列顺序」输入框，分别对应 `series`、`seriesOrder`，直接填写即可。例如第一篇填 `六级学习笔记` 和 `1`，下一篇填同名系列和 `2`。独立文章把两项留空；退出已有系列时清空这两项再保存。也可以在本地复制完整模板，用 GitHub Desktop 上传。

已有文章的系列名称和顺序会显示在表单中，普通正文编辑会保留它们；`settings.content.merge: true` 继续保留作者、语言等表单之外的 Frontmatter 字段。以后每新建一篇，仍需要为新文件填写系列名与序号；不会继承上一篇的系列。文章列表支持按系列名搜索和按系列顺序排序，方便查找已写到第几篇。

## 6. 每次写文章的最短流程

1. 想一个今天能写完的小主题，不必先设计整套目录。
2. 新建一个 `.md`，或在 CMS 点 **Add an entry**；填清标题、日期和一句摘要。
3. 分类沿用大类，标签选本篇知识点；属于连载就填同名 `series` 与下一个 `seriesOrder`。
4. 正文写“结论、例子、下次怎么用”，需要时再加二、三级标题。
5. 写作中保留草稿；检查内容、图片与代码后关闭草稿，再保存或上传。
6. 等博客部署成功，打开文章确认正文和系列导航。

随手记录可以先独立发布，以后再给相关旧文补上同名 `series` 和顺序，把它们整理成系列；不必第一天就决定最终篇数。
