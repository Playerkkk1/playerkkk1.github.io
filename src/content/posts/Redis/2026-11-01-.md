## 1. Redis 的数据模型

Redis 是基于 Key-Value 的数据存储系统：**Key 通常是字符串，Value 可以是不同的数据结构**。


| 类型 | 特征 | 典型用途 | Java 类比（仅帮助理解） |
| ---------------- | ----------------------- | ---------- | --------------------- |
| String | 单个字符串或数字字符串 | 缓存、验证码、计数器 | `String` |
| Hash | 一个 Key 下有多个 field-value | 用户对象、商品属性 | `Map<String, String>` |
| List | 有序、可重复 | 简单队列、任务列表 | `LinkedList` |
| Set | 无序、元素唯一 | 标签去重、共同关注 | `HashSet` |
| Sorted Set（ZSet） | 元素唯一，每个元素关联 score，按分数排序 | 排行榜、积分排序 | 按分数排序的集合 |


**注意：** Redis 还支持 Stream、Bitmap 等其他结构；本篇按基础教学顺序先学经典五种。

## 2. Key 通用命令

通用命令不限定 Value 类型。


| 命令 | 作用 | 示例 |
| ----------------------------------- | -------------------------- | ------------------------------- |
| `EXISTS key` | 判断 Key 是否存在，返回存在的数量 | `EXISTS study:demo` |
| `TYPE key` | 查看 Value 的类型 | `TYPE study:demo` |
| `DEL key` | 删除 Key | `DEL study:demo` |
| `EXPIRE key seconds` | 设置 Key 的过期时间（秒） | `EXPIRE study:demo 60` |
| `TTL key` | 查看剩余过期时间（秒） | `TTL study:demo` |
| `PERSIST key` | 移除 Key 的过期时间 | `PERSIST study:demo` |
| `KEYS pattern` | 按模式查询 Key；**只建议小规模学习环境使用** | `KEYS study:*` |
| `SCAN cursor MATCH pattern COUNT n` | 增量遍历 Key；真实项目优先考虑 | `SCAN 0 MATCH study:* COUNT 10` |


**TTL 的三个常见结果：** 正整数表示剩余秒数`-1` 表示存在但没有过期时间`-2` 表示 Key 不存在。临近过期也可能返回 `0`。

```
SET study:demo hello
EXISTS study:demo
TYPE study:demo
EXPIRE study:demo 120
TTL study:demo
PERSIST study:demo
TTL study:demo
```

**重要提醒：** `KEYS *` 会扫描所有 Key，数据量大时可能阻塞 Redis；不要在生产环境的业务代码中用它遍历键`SCAN` 每次返回一个游标，需要反复调用直到游标返回 `0`，而 `COUNT` 只是数量提示，不保证每次返回指定数量。

### Key 命名与层级模式

推荐格式`业务:类型:ID:字段`，例如 `study:user:1:name`。

```
SET study:user:1:name Player
SET study:user:1:age 20
```

Redis Insight 的层级模式会按照 `:` 分组展示，但 **Redis 中没有因此产生真实文件夹**：上面仍然是两个独立的 Key；删除 `study:user:1:name` 不会删除 `study:user:1:age`。

## 3. String（字符串）

### 3.1 特点与场景

- 最基础的数据类型，存储文本、数字字符串、序列化后的数据等。
- 数值增减命令要求值能够被解释为整数；否则会报错。
- 常用于简单缓存、验证码、访问次数。

### 3.2 常用命令


| 命令 | 作用 |
| ------------------------------- | --------------------- |
| `SET key value` | 设置值，已存在则覆盖；默认会清除原过期时间 |
| `GET key` | 获取值 |
| `MSET k1 v1 k2 v2` | 一次写入多组键值 |
| `MGET k1 k2` | 一次读取多个 Key |
| `SET key value EX seconds` | 设置值并同时设置秒级过期时间 |
| `SET key value NX` | 仅当 Key 不存在时设置 |
| `INCR key` / `DECR key` | 整数加一 / 减一 |
| `INCRBY key n` / `DECRBY key n` | 整数增加 / 减少 n |


```
SET study:string:name Player
GET study:string:name
MSET study:string:lang Java study:string:city Wuhan
MGET study:string:lang study:string:city
SET study:string:code 123456 EX 60
SET study:string:views 0
INCR study:string:views
INCRBY study:string:views 5
DECR study:string:views
GET study:string:views
SET study:string:only-once yes NX EX 30
```

**重点：** `EXPIRE` 修改 TTL 不修改 Value；普通 `SET` 覆盖 Key 时通常会清除旧 TTL。写临时缓存时优先用 `SET key value EX seconds`，避免忘记设置有效期。

## 4. Hash（哈希）

### 4.1 特点与场景

Hash 的结构是`Key -> {field1: value1, field2: value2, ...}`。同一个 Key 下可以保存对象的多个属性。适合对对象字段分别读写，比如昵称、年龄、状态。

### 4.2 常用命令


| 命令 | 作用 |
| ---------------------------------------- | ------------- |
| `HSET key field value [field value ...]` | 设置一个或多个字段 |
| `HGET key field` | 获取指定字段 |
| `HMGET key field1 field2` | 获取多个字段 |
| `HGETALL key` | 获取所有字段与值 |
| `HKEYS key` / `HVALS key` | 获取全部字段名 / 字段值 |
| `HEXISTS key field` | 判断字段是否存在 |
| `HINCRBY key field n` | 对整数字段增减 |
| `HDEL key field` | 删除指定字段 |


```
HSET study:hash:user:1 name Player age 20 city Wuhan
HGET study:hash:user:1 name
HMGET study:hash:user:1 name city
HGETALL study:hash:user:1
HEXISTS study:hash:user:1 age
HINCRBY study:hash:user:1 age 1
HDEL study:hash:user:1 city
```

**易错点：** Hash 的 `field` 不是独立的 Redis Key`EXPIRE` 给 `study:hash:user:1` 设置的是整个 Key 的过期时间，不能用普通 `EXPIRE` 单独给其中一个 field 设置 TTL。

## 5. List（列表）

### 5.1 特点与场景

- **有序，允许重复**，可以从列表头部或尾部增加、弹出元素。
- 适合简单任务队列、消息列表等；更复杂、可靠的消息处理通常考虑 Redis Streams 或专用消息队列。

### 5.2 常用命令


| 命令 | 作用 |
| ----------------------- | ------------------------------------- |
| `LPUSH key v1 [v2 ...]` | 从左边（头部）插入 |
| `RPUSH key v1 [v2 ...]` | 从右边（尾部）插入 |
| `LRANGE key start stop` | 读取指定索引范围`0 -1` 表示全部 |
| `LPOP key` / `RPOP key` | 从左边 / 右边弹出并删除元素 |
| `LLEN key` | 查看列表长度 |
| `LINDEX key index` | 读取指定位置元素 |
| `BLPOP key timeout` | 阻塞式从左侧弹出；无元素时最多等待 timeout 秒`0` 表示一直等待 |


```
RPUSH study:list:tasks taskA taskB taskC
LRANGE study:list:tasks 0 -1
LPUSH study:list:tasks task0
LRANGE study:list:tasks 0 -1
LPOP study:list:tasks
RPOP study:list:tasks
LLEN study:list:tasks
```

第一次 `RPUSH` 后顺序是 `[taskA, taskB, taskC]`；然后 `LPUSH task0` 变成 `[task0, taskA, taskB, taskC]`。

**记忆：** `L` 是 Left（左）`R` 是 Right（右）`PUSH` 插入`POP` 取出并移除`LRANGE` 的索引从 0 开始，结束位置也包含在结果中。

## 6. Set（无序集合）

### 6.1 特点与场景

- **不保证顺序，元素不可重复**。
- 适合去重、标签集合、共同关注、集合交并差。

### 6.2 常用命令


| 命令 | 作用 |
| ------------------------------ | ---------------------- |
| `SADD key member [member ...]` | 添加成员，重复成员不会再次添加 |
| `SMEMBERS key` | 获取全部成员（结果无固定顺序） |
| `SISMEMBER key member` | 判断成员是否存在 |
| `SCARD key` | 获取集合成员数 |
| `SREM key member` | 删除成员 |
| `SINTER key1 key2` | 交集：共同存在的成员 |
| `SUNION key1 key2` | 并集：所有成员去重 |
| `SDIFF key1 key2` | 差集：在 key1 而不在 key2 的成员 |


```
SADD study:set:tags Java Redis Java
SMEMBERS study:set:tags
SCARD study:set:tags
SISMEMBER study:set:tags Redis
SREM study:set:tags Redis

SADD study:set:a Java Redis MySQL
SADD study:set:b Java Python
SINTER study:set:a study:set:b
SUNION study:set:a study:set:b
SDIFF study:set:a study:set:b
```

**易错点：** Set 不是 List，不可依赖插入顺序`SDIFF A B` 和 `SDIFF B A` 通常不相同。

## 7. Sorted Set / ZSet（有序集合）

### 7.1 特点与场景

- 成员（member）**不可重复**，每个成员绑定一个分数（score）。
- Redis 默认按分数从低到高排列；分数相同时还有确定的字典序规则。
- 典型应用是积分排行榜、热度排行。

### 7.2 常用命令


| 命令 | 作用 |
| ------------------------------------------ | ------------------------- |
| `ZADD key score member [score member ...]` | 添加成员及其分数；同一成员再次添加会更新分数 |
| `ZSCORE key member` | 查询成员分数 |
| `ZRANGE key 0 -1` | 按分数从低到高获取全部成员 |
| `ZRANGE key 0 -1 REV` | 按分数从高到低获取全部成员（Redis 6.2+） |
| `ZRANGE key 0 -1 REV WITHSCORES` | 降序并显示分数 |
| `ZRANK key member` | 获取升序排名索引（从 0 开始） |
| `ZREVRANK key member` | 获取降序排名索引（从 0 开始） |
| `ZCARD key` | 获取成员数量 |
| `ZINCRBY key n member` | 给指定成员的分数加 n |
| `ZREM key member` | 删除成员 |


```
ZADD study:zset:ranking 80 Player 95 Alice 72 Bob
ZRANGE study:zset:ranking 0 -1
ZRANGE study:zset:ranking 0 -1 REV WITHSCORES
ZSCORE study:zset:ranking Player
ZREVRANK study:zset:ranking Alice
ZINCRBY study:zset:ranking 10 Player
ZCARD study:zset:ranking
```

第一次降序查询结果依次是 Alice（95）、Player（80）、Bob（72）`ZREVRANK` 返回的**排名索引从 0 开始**，显示给用户时通常需要加 1。

## 8. 五种类型怎么选择？


| 需求 | 选择 | 原因 |
| ------------- | ---------- | ----------- |
| 保存验证码、缓存文章内容 | String | 单个值，读写简单 |
| 网站访问次数 | String | `INCR` 原子自增 |
| 保存用户对象的多个字段 | Hash | 按字段独立读写 |
| 任务按顺序进入与取出 | List | 有序、支持两端操作 |
| 用户标签不能重复 | Set | 自动去重 |
| 求两组用户共同关注的人 | Set | 交集操作 |
| 按积分排序、取 Top N | Sorted Set | 按 score 排序 |


## 9. 入门必记易错点

1. **所有 Key 都有类型**`TYPE key` 查看的是 Value 类型；对不匹配的类型使用命令可能触发 `WRONGTYPE`。
2. **Key 是完整字符串**`user:1:name` 的冒号只是命名约定，Redis Insight 的层级视图不等于真实目录。
3. **TTL 只属于 Key**：普通 `EXPIRE` 不会改变数据的值。
4. **普通** `SET` **会覆盖旧值，默认还会清除旧 TTL**。
5. **List 可重复、Set 不可重复，Sorted Set 不重复且有 score**。
6. `LRANGE key 0 -1` **是查看整个 List**`ZRANGE key 0 -1` 是查看整个 ZSet（默认升序）。
7. **生产环境慎用** `KEYS *`；优先考虑 `SCAN`，不要随意执行 `FLUSHDBFLUSHALL`。
8. **用独立学习前缀防止误操作项目数据**：本篇例子均以 `study:` 开头。
