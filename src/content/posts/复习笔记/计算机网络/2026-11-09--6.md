# 06｜应用层

## 一、应用层的基本概念

应用层是计算机网络体系结构中的最高层，直接为用户的网络应用提供服务。

常见网络应用：

- 浏览器访问网页
- 文件上传与下载
- 电子邮件
- 域名解析
- 网络管理

应用层协议规定了不同应用进程之间交换报文的格式、含义和交互规则。

常见应用层协议：


| 协议 | 主要功能 |
| ---- | -------- |
| HTTP | 网页访问 |
| DNS | 域名解析 |
| FTP | 文件传输 |
| SMTP | 发送电子邮件 |
| POP3 | 接收电子邮件 |
| DHCP | 自动分配网络配置 |
| SNMP | 网络管理 |


## 二、域名系统 DNS

DNS 全称：

Domain Name System

中文：域名系统。

### 1. DNS 的作用

DNS 主要负责将域名转换为 IP 地址。

例如：

用户访问：

[www.example.com](http://www.example.com)

计算机需要通过 DNS 查询对应的 IP 地址，才能建立后续网络通信。

### 2. 为什么需要 DNS？

计算机之间主要使用 IP 地址进行网络通信。

但是 IP 地址不方便人类记忆。

因此使用域名作为更容易记忆的网络名称，再通过 DNS 将域名解析为 IP 地址。

### 3. 域名结构

域名采用层次结构。

例如：

[www.example.com](http://www.example.com)

从右向左可以理解为：

- com：顶级域名。
- example：二级域名。
- www：主机名或子域名标签。

### 4. 域名服务器的分类


| 类型 | 作用 |
| ------- | -------------- |
| 根域名服务器 | 提供顶级域名服务器的查询线索 |
| 顶级域名服务器 | 管理对应顶级域名 |
| 权限域名服务器 | 提供特定域名区域的权威记录 |
| 本地域名服务器 | 代表用户执行 DNS 查询 |


### 5. DNS 查询过程

以浏览器访问 [www.example.com](http://www.example.com) 为例：

1. 浏览器检查本地 DNS 缓存。
2. 如果没有结果，向本地域名服务器发起查询。
3. 本地域名服务器根据缓存或查询过程寻找结果。
4. 通过根域名服务器获得顶级域名服务器的线索。
5. 查询顶级域名服务器。
6. 查询权限域名服务器。
7. 获取对应 IP 地址。
8. 将解析结果返回客户端并进行缓存。

注意：实际 DNS 查询可能采用递归查询和迭代查询的组合，不一定每次都访问全部服务器。

### 6. 递归查询与迭代查询

递归查询：

客户端请求 DNS 服务器查询，服务器负责继续查询并返回最终结果。

迭代查询：

DNS 服务器如果没有最终结果，会返回下一步应查询的服务器线索。

## 三、文件传输协议 FTP

FTP 全称：

File Transfer Protocol

中文：文件传输协议。

### 1. FTP 的作用

FTP 用于在不同主机之间进行文件传输。

常见操作：

- 上传文件。
- 下载文件。
- 删除文件。
- 查看远程目录。
- 管理远程文件。

### 2. FTP 的两个连接

FTP 使用两个 TCP 连接：


| 连接 | 作用 | 常见端口 |
| ---- | ------ | -------------- |
| 控制连接 | 传递控制命令 | TCP 21 |
| 数据连接 | 传输文件数据 | TCP 20（主动模式常见） |


### 3. FTP 的工作特点

控制连接负责传递命令和响应。

数据连接负责实际文件传输。

FTP 的主动模式与被动模式在数据连接的建立方式上有所区别。

注意：不要将 FTP 的控制连接和数据连接混淆。

## 四、万维网 WWW

WWW 全称：

World Wide Web

中文：万维网。

万维网是一个分布式的超媒体系统。

用户可以通过浏览器访问网页、查看图片、播放视频以及使用网络应用。

### 1. URL

URL 全称：

Uniform Resource Locator

中文：统一资源定位符。

URL 用于定位互联网上的资源。

例如：

[https://www.example.com/index.html](https://www.example.com/index.html)

主要组成：

- https：协议。
- [www.example.com：主机名。](http://www.example.xn--com:-3h5fi22a138a./)
- /index.html：资源路径。

### 2. HTTP 协议

HTTP 全称：

HyperText Transfer Protocol

中文：超文本传输协议。

HTTP 是万维网中最重要的应用层协议之一。

主要采用请求-响应模式。

### 3. HTTP 工作过程

1. 用户在浏览器中输入 URL。
2. 浏览器通过 DNS 获取服务器 IP 地址。
3. 浏览器与服务器建立 TCP 连接（HTTPS 还涉及 TLS 握手）。
4. 浏览器发送 HTTP 请求。
5. 服务器处理请求。
6. 服务器返回 HTTP 响应。
7. 浏览器解析并展示页面。

### 4. HTTP 请求报文

HTTP 请求报文主要包含：

- 请求行
- 请求头部
- 空行
- 请求体（如果有）

常见请求方法：


| 方法 | 作用 |
| ------ | --------- |
| GET | 获取资源 |
| POST | 提交数据 |
| PUT | 创建或整体更新资源 |
| DELETE | 删除资源 |
| PATCH | 部分更新资源 |


### 5. HTTP 响应报文

HTTP 响应报文主要包含：

- 状态行
- 响应头部
- 空行
- 响应体

常见状态码：


| 状态码 | 含义 |
| --- | ------- |
| 200 | 请求成功 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 400 | 请求错误 |
| 401 | 未认证 |
| 403 | 禁止访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
| 502 | 网关错误 |
| 503 | 服务暂时不可用 |


### 6. HTTP 与 HTTPS

HTTP：

- 默认端口 80。
- 数据传输本身不提供 TLS 加密。

HTTPS：

- 默认端口 443。
- 在 HTTP 通信基础上使用 TLS 提供加密、身份认证和完整性保护。

### 7. HTTP 的无状态特点

HTTP 本身是无状态协议。

服务器默认不会自动记住前一次请求的全部业务状态。

实际开发中可以通过 Cookie、Session、Token 等机制维护用户状态。

## 五、电子邮件系统

电子邮件系统主要涉及三个部分：

1. 用户代理。
2. 邮件服务器。
3. 邮件发送与接收协议。

### 1. 用户代理

用户通过邮件客户端编写、发送、接收和阅读邮件。

例如：

- Outlook
- Thunderbird
- 网页邮箱

### 2. SMTP

SMTP 全称：

Simple Mail Transfer Protocol

中文：简单邮件传输协议。

主要作用：发送电子邮件。

常见用途：

- 用户向邮件服务器提交邮件。
- 邮件服务器之间传递邮件。

常见端口：

- TCP 25：服务器之间传递邮件。
- TCP 587：常见邮件提交端口。

### 3. POP3

POP3 全称：

Post Office Protocol Version 3

中文：邮局协议第三版。

主要作用：从邮件服务器接收邮件。

常见端口：

TCP 110。

### 4. IMAP

IMAP 全称：

Internet Message Access Protocol

中文：互联网邮件访问协议。

主要作用：在服务器端管理和访问邮件。

常见端口：

TCP 143。

### 5. SMTP、POP3 与 IMAP 对比


| 协议 | 主要功能 | 常见端口 |
| ---- | ------- | ------ |
| SMTP | 发送邮件 | 25、587 |
| POP3 | 接收邮件 | 110 |
| IMAP | 访问和管理邮件 | 143 |


## 六、动态主机配置协议 DHCP

DHCP 全称：

Dynamic Host Configuration Protocol

中文：动态主机配置协议。

### 1. DHCP 的作用

DHCP 用于自动向主机分配网络配置。

常见配置内容：

- IP 地址。
- 子网掩码。
- 默认网关。
- DNS 服务器地址。

### 2. DHCP 工作过程

常见过程称为 DORA：


| 步骤 | 报文 | 作用 |
| --- | -------- | -------------- |
| 1 | Discover | 客户端寻找 DHCP 服务器 |
| 2 | Offer | 服务器提供地址配置 |
| 3 | Request | 客户端请求使用地址 |
| 4 | ACK | 服务器确认分配 |


记忆：

Discover → Offer → Request → ACK。

### 3. DHCP 的常见端口

- 服务器：UDP 67。
- 客户端：UDP 68。

DHCP 使用 UDP 进行通信。

## 七、网络管理协议 SNMP

SNMP 全称：

Simple Network Management Protocol

中文：简单网络管理协议。

主要用于监视和管理网络设备。

例如：

- 路由器。
- 交换机。
- 网络服务器。

### 主要组成

- 管理站：负责管理网络设备。
- 代理：运行在被管理设备上。
- MIB：管理信息库。

SNMP 常见端口：

- UDP 161：管理请求与响应。
- UDP 162：常用于接收通知和陷阱报文。

## 八、常见应用层协议及端口汇总


| 协议 | 传输层协议 | 常见端口 | 作用 |
| ------ | ------- | ------- | -------- |
| HTTP | TCP | 80 | 网页访问 |
| HTTPS | TCP | 443 | 安全网页访问 |
| FTP | TCP | 21、20 | 文件传输 |
| SSH | TCP | 22 | 安全远程登录 |
| Telnet | TCP | 23 | 远程登录 |
| SMTP | TCP | 25 | 邮件传输 |
| DNS | UDP/TCP | 53 | 域名解析 |
| DHCP | UDP | 67、68 | 动态分配网络配置 |
| POP3 | TCP | 110 | 接收邮件 |
| IMAP | TCP | 143 | 邮件访问 |
| SNMP | UDP | 161、162 | 网络管理 |


注意：

端口号是常见默认值，实际部署中可以进行配置调整。DNS 不仅使用 UDP，也会在某些情况下使用 TCP。

## 九、本章易混淆知识点

### 1. DNS 与 DHCP

DNS：将域名解析为 IP 地址。

DHCP：自动分配 IP 地址等网络配置。

### 2. SMTP 与 POP3

SMTP：发送邮件。

POP3：接收邮件。

### 3. HTTP 与 HTTPS

HTTP：不提供 TLS 加密保护。

HTTPS：使用 TLS 提供加密和身份认证等安全能力。

### 4. FTP 控制连接与数据连接

控制连接传输命令。

数据连接传输文件。

### 5. TCP 与 UDP 在应用层的使用

HTTP/1.1 和 HTTP/2 通常使用 TCP。

HTTP/3 使用 QUIC，基于 UDP。

DNS 查询通常使用 UDP，但也可能使用 TCP。
