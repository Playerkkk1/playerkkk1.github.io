## 一、下一代互联网的基本概念

随着互联网规模不断扩大，传统 IPv4 网络逐渐面临地址资源不足、路由表规模增长以及网络服务需求不断提高等问题。

因此，互联网技术不断发展，出现了 IPv6、多协议标签交换 MPLS 和 P2P 等相关技术。

本章主要学习：

1. IPv6：解决 IPv4 地址空间不足等问题。
2. MPLS：提高网络转发效率，并支持流量工程等功能。
3. P2P：实现网络中多个节点之间的直接资源共享。

## 二、IPv6

IPv6 全称：

Internet Protocol Version 6

中文：互联网协议第六版。

### 1. IPv6 出现的原因

IPv4 地址长度为 32 bit，理论地址空间为：

2³² 个地址。

随着互联网设备数量不断增加，IPv4 地址资源逐渐不足。

IPv6 将地址长度扩展到 128 bit，极大扩大了地址空间。

IPv6 地址空间为：

2¹²⁸ 个地址。

### 2. IPv6 的主要特点

- 地址长度为 128 bit。
- 地址空间非常大。
- 采用更简化的基本首部。
- 支持自动配置。
- 改进了扩展首部机制。
- 不使用 IPv4 首部检验和。
- 不允许路由器对 IPv6 数据报进行分片。

注意：IPv6 并不是简单地将 IPv4 地址扩展，而是对网络层协议进行了改进。

### 3. IPv6 地址表示方法

IPv6 地址由 128 bit 组成。

通常采用冒号分隔的十六进制表示法。

例如：

2001:0db8:0000:0000:0000:0000:0000:0001

IPv6 地址通常分为 8 组，每组 16 bit。

### 4. IPv6 地址压缩规则

IPv6 地址可以使用以下两种方式简化表示。

**规则一：省略每组前面的连续 0。**

例如：

2001:0db8:0000:0000:0000:0000:0000:0001

可以写成：

2001:db8:0:0:0:0:0:1

**规则二：连续的全零组可以使用 :: 压缩。**

例如：

2001:db8:0:0:0:0:0:1

可以写成：

2001:db8::1

注意：

一个 IPv6 地址中，:: 最多只能出现一次，否则无法确定省略了多少组 0。

### 5. IPv6 基本首部

IPv6 基本首部固定长度为 40 Byte。

主要字段：


| 字段 | 作用 |
| ------ | ------------- |
| 版本 | 标识 IP 版本 |
| 通信量类别 | 区分不同类型的流量 |
| 流标号 | 标识属于同一数据流的分组 |
| 有效载荷长度 | 表示基本首部之后的数据长度 |
| 下一个首部 | 标识后续扩展首部或上层协议 |
| 跳数限制 | 限制数据报经过的路由器数量 |
| 源地址 | 发送方 IPv6 地址 |
| 目的地址 | 接收方 IPv6 地址 |


### 6. IPv4 与 IPv6 对比


| 比较项目 | IPv4 | IPv6 |
| ----- | ------------- | ------------- |
| 地址长度 | 32 bit | 128 bit |
| 地址表示 | 点分十进制 | 冒号分隔十六进制 |
| 首部长度 | 可变，最小 20 Byte | 固定 40 Byte |
| 首部检验和 | 有 | 无 |
| 广播 | 支持广播 | 不使用广播，使用组播等机制 |
| 分片 | 源主机和路由器均可能参与 | 仅源节点负责分片 |
| 地址空间 | 较小 | 极大 |


### 7. IPv6 的地址类型

IPv6 常见地址类型：

- 单播地址：标识一个网络接口。
- 多播地址：标识一组网络接口。
- 任播地址：分配给一组接口，数据发送到其中距离最近的一个。

注意：IPv6 不使用 IPv4 那种广播地址。

## 三、IPv6 过渡技术

IPv4 和 IPv6 并不能在所有情况下直接互相通信，因此需要过渡技术。

### 1. 双协议栈

一台设备同时支持 IPv4 和 IPv6 两种协议。

根据通信目标选择对应的协议。

### 2. 隧道技术

将一种协议的数据报封装在另一种协议的数据报中传输。

例如：

通过 IPv4 网络传输 IPv6 数据报。

### 3. 协议转换

通过转换机制实现 IPv4 与 IPv6 网络之间的通信。

例如：

NAT64 可以帮助 IPv6 网络中的设备访问 IPv4 网络中的服务。

## 四、多协议标签交换 MPLS

MPLS 全称：

Multi-Protocol Label Switching

中文：多协议标签交换。

### 1. MPLS 的基本概念

MPLS 是一种结合标签转发与网络层路由的技术。

其主要思想是：

在数据分组进入 MPLS 网络时，为其分配标签，后续节点可以根据标签进行转发。

### 2. MPLS 的基本工作过程

1. 数据分组进入 MPLS 网络。
2. 入口标签边缘路由器为分组添加标签。
3. MPLS 网络中的标签交换路由器根据标签进行转发。
4. 数据分组到达出口节点。
5. 移除标签后继续进行后续转发。

### 3. MPLS 的重要概念

**标签**

用于标识数据分组在 MPLS 网络中的转发信息。

**标签交换路由器 LSR**

根据标签转发数据分组的设备。

**标签边缘路由器 LER**

位于 MPLS 网络边缘，负责添加或移除标签。

### 4. MPLS 的主要特点

- 支持基于标签的转发。
- 可以支持流量工程。
- 能够建立标签交换路径。
- 可以用于构建 VPN 等网络服务。
- 可以与多种网络层协议配合使用。

## 五、P2P 网络

P2P 全称：

Peer-to-Peer

中文：对等网络。

### 1. P2P 的基本概念

P2P 网络是一种强调节点之间直接交换资源的网络组织方式。

在传统客户-服务器模式中：

- 客户端请求资源。
- 服务器提供资源。

在 P2P 网络中：

- 每个节点既可以请求资源。
- 也可以向其他节点提供资源。

### 2. P2P 的主要特点

- 节点之间可以直接通信。
- 节点可以同时充当资源提供者和使用者。
- 资源分布在多个节点中。
- 具有一定的分布式特征。
- 可以降低对单一中心服务器的依赖。

### 3. P2P 的常见应用

- 文件共享。
- 分布式内容传输。
- 多节点资源交换。
- 分布式计算。

### 4. P2P 与 C/S 对比


| 比较项目 | C/S 模式 | P2P 模式 |
| ----- | -------- | ----------- |
| 组织方式 | 客户端与服务器 | 对等节点 |
| 资源提供者 | 主要由服务器提供 | 多个节点共同提供 |
| 中心化程度 | 较高 | 通常较低 |
| 扩展方式 | 依赖服务器能力 | 可通过增加节点扩展资源 |
| 典型特点 | 集中管理 | 分布式共享 |


## 六、本章易混淆知识点

### 1. IPv4 与 IPv6

IPv4 地址长度为 32 bit。

IPv6 地址长度为 128 bit。

### 2. IPv6 与 IPv4 的首部

IPv6 基本首部固定为 40 Byte，不包含首部检验和。

### 3. 双协议栈与隧道技术

- 双协议栈：设备同时支持 IPv4 和 IPv6。
- 隧道技术：将一种协议的数据封装到另一种协议中传输。

### 4. MPLS 与普通 IP 转发

- 普通 IP 转发：主要根据目的 IP 地址和路由表进行转发。
- MPLS：在 MPLS 网络内部主要根据标签进行转发。

### 5. C/S 与 P2P

- C/S：服务器集中提供服务。
- P2P：多个节点可以共同提供和使用资源。
