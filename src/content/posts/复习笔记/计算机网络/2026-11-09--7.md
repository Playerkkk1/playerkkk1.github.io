# 07｜网络安全

## 一、网络安全的基本概念

网络安全是指通过技术和管理措施，保护网络系统及其数据，避免受到未经授权的访问、破坏、泄露和攻击。

网络安全主要关注以下几个方面：

### 1. 机密性

确保信息只能被授权用户访问。

例如：通过加密技术，防止其他人直接读取传输中的数据。

### 2. 完整性

确保数据在传输和存储过程中没有被非法修改。

例如：通过哈希校验等方式检测数据是否发生变化。

### 3. 可用性

确保授权用户能够正常使用网络服务。

例如：防止网络服务因故障或攻击而无法正常访问。

### 4. 身份鉴别

确认通信双方的身份是否合法。

例如：通过密码、数字证书等方式确认用户或服务器身份。

## 二、密码学的基本概念

密码学主要研究如何通过数学方法保护信息。

基本术语：


| 名称 | 含义 |
| ---- | ------------ |
| 明文 | 未加密的原始信息 |
| 密文 | 加密后的信息 |
| 加密 | 将明文转换为密文 |
| 解密 | 将密文恢复为明文 |
| 密钥 | 控制加密和解密过程的信息 |
| 密码算法 | 实现加密与解密的算法 |


基本过程：

明文 → 加密算法 → 密文

密文 → 解密算法 → 明文

## 三、对称加密

对称加密也称为共享密钥加密。

### 1. 基本原理

通信双方使用相同的密钥进行加密和解密。

发送方使用密钥将明文加密为密文。

接收方使用相同的密钥将密文恢复为明文。

### 2. 主要特点

- 加密和解密使用相同的密钥。
- 加密速度通常较快。
- 适合大量数据加密。
- 密钥需要安全地分发和保存。

### 3. 常见算法

- DES：数据加密标准，属于较早期的对称加密算法，现已不适合安全应用。
- 3DES：三重数据加密算法。
- AES：高级加密标准，目前广泛使用。

### 4. 优缺点

优点：

- 运算速度快。
- 适合大规模数据加密。

缺点：

- 通信双方需要安全共享密钥。
- 多个用户之间需要管理大量密钥。

## 四、非对称加密

非对称加密也称为公钥密码体制。

### 1. 基本原理

非对称加密使用一对密钥：

- 公钥：可以公开。
- 私钥：必须由所有者妥善保管。

公钥和私钥之间存在数学上的关联，但不能在实际安全条件下轻易由公钥推导出私钥。

### 2. 加密通信过程

假设 A 想向 B 发送机密信息。

1. B 将自己的公钥公开。
2. A 获取 B 的公钥。
3. A 使用 B 的公钥加密信息。
4. B 使用自己的私钥解密信息。

这样可以保护信息的机密性。

### 3. 常见算法

RSA 是经典的公钥密码算法。

### 4. 主要特点

优点：

- 不需要直接向通信对象传递私钥。
- 可以支持数字签名。
- 有助于解决密钥分发问题。

缺点：

- 运算速度通常比对称加密慢。
- 需要额外机制确认公钥的真实性。

## 五、对称加密与非对称加密对比


| 比较项目 | 对称加密 | 非对称加密 |
| ---- | ---------- | ---------- |
| 密钥数量 | 通信双方共享密钥 | 公钥与私钥一对 |
| 加密速度 | 通常较快 | 通常较慢 |
| 密钥分发 | 需要安全分发共享密钥 | 公钥可以公开 |
| 典型算法 | AES | RSA |
| 主要用途 | 大量数据加密 | 密钥交换、数字签名等 |


### 混合加密

实际网络通信中，通常结合使用两种加密方式。

例如 HTTPS 使用 TLS：

1. 通过证书和密钥协商机制建立安全通信参数。
2. 协商得到会话密钥。
3. 使用高效的对称加密算法保护后续大量数据。

注意：现代 TLS 通常使用基于临时密钥的密钥交换机制，而不是简单地使用服务器 RSA 公钥直接加密会话密钥。

## 六、数字摘要与哈希函数

### 1. 数字摘要

数字摘要是通过哈希函数将任意长度的数据转换为固定长度的摘要值。

例如：

原始数据 → 哈希函数 → 摘要

### 2. 哈希函数的主要特点

- 输入数据长度可以不同。
- 输出摘要长度固定。
- 相同输入通常产生相同摘要。
- 微小的数据变化可能导致摘要明显变化。
- 从摘要反向恢复原始数据在计算上不可行。

### 3. 常见算法

- MD5：产生 128 bit 摘要，但已不适合安全用途。
- SHA-1：已不适合需要抗碰撞安全性的场景。
- SHA-256：属于 SHA-2 系列，广泛使用。

注意：哈希函数本身不是加密算法，不能通过解密得到原始明文。

## 七、数字签名

数字签名主要用于验证消息来源和完整性，并支持不可否认性。

### 1. 基本原理

数字签名通常使用发送方的私钥生成签名，接收方使用发送方的公钥验证签名。

基本过程：

1. 发送方对原始消息计算数字摘要。
2. 发送方使用自己的私钥对摘要进行签名。
3. 将原始消息和数字签名一起发送给接收方。
4. 接收方使用发送方的公钥验证签名。
5. 接收方重新计算消息摘要并进行比较。

如果验证通过，说明签名与当前消息相匹配。

### 2. 数字签名的作用

- 验证消息来源。
- 检测消息是否被修改。
- 支持不可否认性。

### 3. 数字签名与数据加密的区别


| 比较项目 | 数据加密 | 数字签名 |
| ------ | --------------- | --------------- |
| 主要目的 | 保密 | 验证身份与完整性 |
| 典型密钥使用 | 接收方公钥加密，接收方私钥解密 | 发送方私钥签名，发送方公钥验证 |
| 关注重点 | 机密性 | 身份鉴别、完整性 |


## 八、数字证书与身份鉴别

### 1. 身份鉴别

身份鉴别是确认通信对象或用户身份是否合法的过程。

常见方式：

- 密码认证。
- 短信验证码。
- 数字证书。
- 多因素认证。

### 2. 数字证书

数字证书用于将某个实体的身份与其公钥关联起来。

通常由可信的证书认证机构 CA 签发。

证书包含：

- 证书持有者信息。
- 公钥信息。
- 证书有效期。
- CA 的数字签名等。

### 3. CA 的作用

CA 全称：

Certificate Authority

中文：证书认证机构。

主要负责签发和管理数字证书，帮助通信双方确认公钥与身份之间的关系。

## 九、防火墙

### 1. 防火墙的基本概念

防火墙是一种网络安全防护技术，用于根据预先设置的安全策略控制网络之间的数据通信。

主要作用：

- 控制网络访问。
- 阻止未经授权的连接。
- 限制不符合安全策略的数据流。
- 保护内部网络。

### 2. 防火墙的常见类型

#### 包过滤防火墙

根据数据包中的地址、端口、协议等信息进行过滤。

#### 状态检测防火墙

不仅检查数据包本身，还会跟踪网络连接状态，根据连接状态判断是否允许通信。

#### 应用层代理防火墙

通过代理方式处理应用层通信，可以根据应用层内容实施更细致的访问控制。

### 3. 防火墙的局限性

防火墙并不能解决所有网络安全问题。

例如：

- 无法保证内部用户一定安全。
- 不能完全防止恶意软件。
- 无法替代身份认证和数据加密。
- 无法保证所有应用程序不存在漏洞。

## 十、本章易混淆知识点

### 1. 对称加密与非对称加密

- 对称加密：使用相同的共享密钥。
- 非对称加密：使用公钥和私钥。

### 2. 加密与哈希

- 加密：可以通过正确的密钥解密恢复数据。
- 哈希：用于生成固定长度摘要，不是可逆加密。

### 3. 数字签名与数字证书

- 数字签名：用于验证消息来源和完整性。
- 数字证书：用于证明公钥与身份之间的关联。

### 4. 数字签名与数据加密

- 加密主要解决机密性。
- 签名主要解决身份验证和完整性。

### 5. 防火墙与加密技术

- 防火墙：控制网络通信。
- 加密：保护数据内容。
